# AI Merchant Growth & Campaign Orchestrator

A multi-agent system that takes a merchant's business objective and real merchant data, runs it through a crew of AI agents to generate a full marketing campaign, validates the resulting commerce action through a deterministic policy engine, executes it safely on **Razorpay Test Mode**, measures the real outcome, and proposes an adapted next campaign based on that outcome.

---

## The problem it solves

Small merchants don't have a marketing team. This system acts as one — turning "I want to grow sales on my running shoe store" into a researched, written, art-directed campaign, backed by real merchant data (not guesses), checked against business policy before anything touches money, executed as a real Razorpay test-mode transaction, and measured/adapted like an actual growth loop instead of a one-shot generator.

```
└─────────┬─────────┘

┌───────────────────┐

          ▼
┌───────────────────┐
│   Manager Agent     │  assembles final brief + proposes a commerce action
└─────────┬─────────┘
          ▼
┌────────────────────────┐
│   Policy Engine         │  validates action, checks idempotency
└─────────┬──────────────┘
          ▼
┌────────────────────────┐
│ Razorpay Test Executor  │  executes on Razorpay test-mode Orders API
│ (falls back to Local    │
│  Safe Executor if no    │
│  test keys are set)     │
└─────────┬──────────────┘
          ▼
┌────────────────────────┐
│   Measurement            │  records real campaign outcome (no fabricated numbers)

└────────────────────────┘
```

Built on **CrewAI**, with a **FastAPI** wrapper (`api.py`) so the whole pipeline can be triggered over HTTP as well as from the CLI (`main.py`).

## Tech stack

- **CrewAI** — agent orchestration (Research / Copywriter / Art Director / Manager)
- **Groq** — primary LLM backend, selected via a free-backend auto-selector (`llm_config.py`) so the project runs on a free tier
- **Razorpay Test Mode API** (official Python SDK) — real commerce action execution, auto-selected when `RAZORPAY_KEY_ID` / `RAZORPAY_KEY_SECRET` are set; falls back to a `LocalSafeExecutor` stub otherwise
- **FastAPI** — HTTP interface
- **Pydantic** — structured input/output validation

## What each stage actually does

1. **Structured input** — merchant business objective + merchant dataset, validated with Pydantic (rejects malformed input like a bare number typed into `target_customers` instead of letting it silently become a fabricated stat)
2. **Research Agent** — grounds the campaign in the real merchant dataset via a dedicated lookup tool, with an authoritative-count/no-filter-warning check so it can't quietly invent numbers
3. **Copywriter + Art Director Agents** — generate campaign copy and visuals
4. **Manager Agent** — assembles the final brief and proposes a structured commerce action (plain-text JSON, parsed manually — see "what broke" below)
5. **Policy Engine** — deterministically validates the proposed action (product match, business rules) and checks for duplicate/idempotent actions *before* anything touches Razorpay
6. **Execution** — real Razorpay test-mode Orders API call via the official SDK, with graceful `EXECUTION_FAILED` handling (a failed financial action is never auto-retried and never written to the idempotency store)
7. **Measurement** — pure deterministic code, no LLM involved; numbers must come from real/manual entry, never generated by an agent
8. **Feedback loop** — proposes (never auto-executes) an adapted Campaign #2 based on the measured result
9. **Benchmarking** (`benchmark.py`) — computes real metrics from `run_history.jsonl`, `policy_log.jsonl`, and `campaign_results.json`: workflow success rate, avg tokens/cost/duration, policy rejection/duplicate/approval rates, campaign objective achievement rate. Metrics with no underlying data (e.g. agent failure rate) are explicitly labeled as not-yet-measurable rather than invented.

## What broke, and how I got out

- **Delegation bug burning the rate limit:** the Manager agent had `allow_delegation` defaulting on, so it kept re-delegating to the Art Director mid-task, silently burning Groq's TPM until requests started failing. Fixed by explicitly setting `allow_delegation=False`.
- **Silent output truncation:** the Manager's final brief sometimes cut off after a couple of lines with no error — traced to `max_tokens=700` in the LLM config, fixed by raising it to 3000.
- **Fabricated data slipping through validation:** a bare number typed into `target_customers` was silently turned into a fabricated "5,000 customers" brief instead of being rejected. Fixed with a Pydantic validator plus an authoritative-count/no-filter-warning addition to the merchant data lookup tool.
- **CrewAI's structured output fighting Groq:** `output_pydantic` forced a tool-calling path Groq doesn't support cleanly, causing failures in the action-proposal step. Replaced with plain-text JSON output, parsed manually.
- **The LLM renaming the product:** the proposed commerce action kept paraphrasing/rebranding the product name, which the policy engine's product-match check correctly rejected. Fixed with a deterministic override that forces the proposed action's product name to match the campaign's authoritative product field.
- **A failure in the action-proposal step could destroy an already-saved brief:** split the action proposal into its own separate Crew run so a downstream failure can't wipe out work that already succeeded upstream.
- **Two conflicting Pydantic model definitions:** `models.py` ended up with two classes of the same name (`CampaignAdaptationProposal`) — Python silently used the wrong one. Caught via a standalone test script before it ever reached a live run.
- **Rate-limit retries:** added a retry that parses Groq's own "try again in Xs" hint from the error response before retrying once, instead of guessing a backoff.

- End-to-end: structured input → grounded research → policy-checked action → Razorpay test-mode execution → measurement → adapted next-campaign proposal

- Benchmarking script validated against hand-checked synthetic data before being run against real logs

## Setup

```bash
git clone <this-repo-url>
cd <repo-folder>
python -m venv venv
venv\Scripts\Activate.ps1        # Windows
# source venv/bin/activate       # macOS/Linux

pip install -r requirements.txt
```

Create a `.env` file (not committed — see `.gitignore`) with:

```
GROQ_API_KEY=your_key_here
RAZORPAY_KEY_ID=your_test_key_id       # optional — falls back to local stub if unset
RAZORPAY_KEY_SECRET=your_test_key_secret
```

Run:

```bash
python main.py
```

Or serve over HTTP:

```bash
uvicorn api:app --reload
```

